01Project Overview

The cornerstone of EE 5345 motion.

This project is the cornerstone lab of the EE 5345 PLC Motion Control graduate course. The assignment was to build the same single-axis motion-control application on two different industrial-automation ecosystems — Rockwell (Lab 1R) and Siemens (Lab 1S) — so that the logical design, the PackML state model, and the operator interface stay constant while the hardware, the configuration idioms, and the vendor toolchains all change underneath.

The deliverables: a complete Studio 5000 Logix Designer project that drives a Kinetix 5300 servo through a 100 mm linear move and return, and a complete TIA Portal V18 project that drives a SINAMICS S120 servo through a 1000° rotary move and return — both wrapped in a shared simplified PackML state machine and exercised through operator pushbuttons, indicator lamps, and servo tuning trends.

The project builds the practical muscle every entry-level motion engineer needs: configuring a servo drive and its axis object from scratch, writing a step-sequenced motion procedure, closing an operator-facing mode/state machine on top of it, and tuning the velocity and position loops on a real drive with live trend data.

02System Architecture

Three layers, two implementations.

Both implementations share the same three-layer ISA-TR88 structure so the ported design reads cleanly across vendors. A Unit Procedure (UN01_ExampleMachine) owns the PackML state machine and mode toggle, an Equipment Module (EM01_Axis01) owns one servo axis and the manual-jog controls, and a small stack of Control Modules (CM00_Procedure, CM02_ServoAxisObject, CM03_ServoAxisJog) encapsulates the low-level motion primitives. Adding a second axis is an EM-level instantiation rather than a new program.

04Shared PackML State Machine

Six states, two modes, identical semantics.

Both projects implement the same simplified ISA-TR88 PackML state model with two modes (Manual, Produce) and six states. A first-scan rung latches Manual mode and Aborted state so the unit comes up known; HMI_I_ModeChgReq is edge-triggered to toggle between modes (only while Aborted). Indicator lamps drive LA_IDLE / LA_EXECUTE / LA_ABORTED with a 1 Hz flash timer that distinguishes the transient states (Resetting, Starting, Aborting) from their steady counterparts.

05Lamp Flash & Shared DB

Same TON, different syntax.

A small but instructive cross-vendor detail: indicator lamps in PackML have to distinguish steady states (Idle, Execute, Aborted) from transient states (Resetting, Starting, Aborting). Both platforms solve it the same way — a 1 Hz TON ticking a Lamp_Flash bit, then per-state output rungs that OR the steady-state bit with the transient state AND Lamp_Flash. Different syntactic dressing, identical logic.

Fig. 08 · Rockwell UN01 MainRoutine — Indicator Lamps
Studio 5000. Rung 1 is the JSR to UP01_PackML. Rung 3 self-resetting TON with Lamp_Flash_Tmr.DN on the rung condition (1000 ms preset). Rung 4 compares Lamp_Flash_Tmr.ACC > 500 to produce the 50 % duty Lamp_Flash bit. Rungs 5-7 drive LA_IDLE / LA_EXECUTE / LA_ABORTED on Local:2:O with the OR-pattern: steady state, OR transient state AND Lamp_Flash.
Fig. 09 · Siemens UN01_00_Main [FB100] — Same Pattern
TIA Portal. Network 1 calls FB105 UN01_UP01_PackML. Network 2 holds the Lamp_Flash_Tmr TON_TIME instance (T#1s preset, self-resetting via #Lamp_Flash_Tmr.Q-NC). Network 3 compares Lamp_Flash_Tmr.ET >= T#500ms for the flash bit. Networks 4-6 drive Q4.0 LA_IDLE, Q4.1 LA_EXECUTE, etc. with the same steady-OR-transient&flash structure as Rockwell.

Shared PackML data block — DB10

Where the Rockwell project uses program-scoped tags imported from the Axis_Example_CLogix_PackML_Tags.csv, the Siemens project bundles every inter-FB PackML signal into a single global data block, DB10 PackML. Every FB in both the unit and equipment programs references this DB — it is what lets the FB105 UP01_PackML on the unit side communicate state to every CM00 on the equipment side without explicit InOut wiring.

Fig. 10 · Siemens DB10 PackML — Shared State Data Block
Global DB declaration. Boolean state bits (Mode_Manual, Mode_Produce, UP_Idle, UP_Starting, UP_Execute, UP_Aborting, UP_Aborted, UP_Resetting) plus five Array[0..31] of Bool per-EM completion arrays (EM_Aborting_Done, EM_Execute_Done, EM_Resetting_Done, EM_Starting_Done, EM_MotionInstError) — one slot per equipment module instance, indexed by EM_Number.

01
Rockwell / Studio 5000

Motion foundation — tree, drive, axis

Controller tree populated with 1756-IB32 (slot 1), 1756-OB16I (slot 2), and 1756-EN2TR (slot 7) with Time Sync and Motion enabled. MainTask switched to a 30 ms periodic task, programs UN01_ExampleMachine + EM01_Axis01 added with their routines. Full axis properties commissioned: Motor catalog, Scaling (Linear Actuator in mm via the belt-and-pulley), Polarity, Load (Load Ratio 2.0), Position Loop (6.5 Hz, 100 % FF), Velocity Loop (26 Hz), Torque Loop (1000 Hz), Planner, Homing (Active mode, NO limit), and Actions.
02
Rockwell / Ladder

PackML state machine + 10-step motion procedure

UP01_PackML implements the 6-state model with Manual/Produce mode toggle. CM00_Procedure holds the ten-step motion sequence: Step_1 MSO drive enable; Step_2 500 ms dwell; Step_3 MAM to +100 mm via Wrk_MI_Move1; Step_4 1 s dwell; Step_5 MAM to −100 mm via Wrk_MI_Move2; 6–9 MSF cleanup; Step_10 latches EM_ExecuteDone. Error handling centralized — any .ER bit one-shots into EM_ProcedureError which the unit consumes to transition into Aborting.
03
Rockwell / Tuning

Autotune, then manual loop tuning with trends

Autotune run first (Basic / Medium / Rigid, 100 mm travel, 100 mm/s, Forward Bi-directional). Trend built with CommandPosition, PositionError, CommandVelocity, VelocityError, CurrentCommand in isolated-plot mode. Manual tune: velocity loop tuned first by doubling Vp bandwidth until oscillation, then halving; Vi bandwidth started at ¼ of Vp and adjusted to zero error. Position loop then tuned on top. Jerk swept at 10 % / 50 % / 100 % of MAM time and compared against a trapezoidal profile.

06
Siemens / Trace

Tune the Kv loop, sweep precontrol & smoothing

Online via TIA Portal Go online on the PN/IE interface. Watch Window set up with HMI_I_JogPositive / JogNegative, HMI_I_SelectJogAxis = 1, Par_Jog_Speed = 20.0, Par_Jog_Accel = Decel = 500.0. SCL added to compute Axis_1_PositionError and Axis_1_VelocityError. Trace built with five pens. Velocity loop is pre-tuned in STARTER, so only the position loop tuned in the PLC — Kv doubled from default 10 until ringing, then halved. Precontrol swept 25 %, 50 %, 100 %; smoothing time swept 0.05 s, 0.1 s, 0.2 s; finally jerk-limited vs. trapezoidal (jerk = −1.0) compared head-to-head.
08The CM00 Procedure

Ten steps, one error funnel.

The motion procedure that runs when PackML is in Execute. Rung 1 is the first-scan initializer that COPs a default MI_Init motion instruction into both working tags. Rung 2 unlatches every Step_1 … Step_10 bit on first scan, during UP_Resetting, and during UP_Idle, so the procedure always restarts clean from Step_1. Rung 3 sets the No_Steps_Active helper bit when none of the ten step bits is high — the condition the unit uses to seed Step_1 when Execute begins.

Fig. 05 · Rockwell CM00_Procedure — EXECUTE state motion steps
Rung 1 COPs MI_Init into Wrk_MI_Move1 and Wrk_MI_Move2 on first scan. Rung 2 unlatches every step bit on first scan / UP_Resetting / UP_Idle. Rung 3 derives No_Steps_Active from the AND-NOT of all ten step bits. Subsequent rungs (off-screen) hold the actual MSO / dwell / MAM / MSF chain through Step_10 and the centralized EM_ProcedureError latch.

The actual move — MAM instruction detail

Inside Step_1 / Step_6 on the Rockwell side, the heavy lifting is a single MAM (Motion Axis Move) instruction parameterized for the tuned profile. On Step_1 PC completion, the rung unlatches Step_1 and latches Step_2 — the canonical OTL/OTU handoff that drives the entire ten-step sequence.

Fig. 06 · Rockwell MAM Instruction — Step_1 Axis +Move 1 Unit
Studio 5000 MAM detail. Axis = Ref_ServoAxis (Axis_1), Motion Control = Wrk_MI_Move1, Move Type 1 (Absolute), Position 1, Speed 50 units/sec, Accel/Decel Rate 500 units/sec², S-Curve profile with Accel/Decel Jerk = 10 % of Time, Merge Disabled. On Wrk_MI_Move1.PC the rung unlatches Step_1 and latches Step_2.

Siemens EM01 — FB call orchestration

The Siemens equivalent doesn't have routines under a program — instead, EM01_00_Main [FB200] calls three sub-FBs in sequence. Network 3 wires CM00_Procedure, CM03_ServoAxisJog, and CM02_ServoAxisObject with the Ref_ServoAxis reference to Axis_1 as an InOut parameter, and Par_Jog_Speed / Par_Jog_Accel / Par_Jog_Decel flowing through as jog parameters — the exact same wiring the Rockwell project does through shared program tags.

Fig. 07 · Siemens EM01_00_Main [FB200] — Network 3 FB Calls
TIA Portal V18 LAD. Static area declares CM00_Procedure, CM02_ServoAxisObject, and CM03_ServoAxisJog as multi-instance DBs. Network 2 moves 20.0 / 500.0 / 500.0 into Par_Jog_Speed / Accel / Decel on first scan. Network 3 calls FB201 (CM00 procedure with MotionStepsError and No_Steps_Active outputs), FB204 (jog with axis & speed/accel/decel), and FB203 (servo axis object). Each FB takes #EM_Number as input and Axis_1 as Ref_ServoAxis.

10Outcome

Two working builds, one fluency.

The final deliverable is a pair of working single-axis motion projects that implement the same logical design on two different vendor ecosystems. The Rockwell project drives a Kinetix 5300 servo through a 100 mm forward / 1 s dwell / 100 mm reverse cycle with autotune-derived S-curve profiles, a PackML-compliant unit procedure, and live trend capture for tuning verification. The Siemens project drives a SINAMICS S120 servo through a +1000° / 1 s dwell / −1000° cycle with the same PackML state logic rebuilt in F-block LAD and a matching trace capture. Beyond the working demos, the most valuable outcome was the back-to-back experience of expressing the exact same logical design in two different vendor idioms — OTL/OTU vs. S/R coils, ONS vs. P_TRIG, Motion Axis Move vs. MC_MoveRelative, Motion Group / 2.0 ms update vs. MC-Servo OB91 / Factor 2, Studio 5000 Autotune vs. TIA Portal Kv / Precontrol — which is precisely the translation any controls engineer needs to make fluently on the factory floor.
